# i18n Design — Internacionalização do Portfolio (PT + EN)

**Data:** 2026-06-19  
**Stack:** Next.js 14 App Router, TypeScript, Tailwind CSS, next-intl  
**Locales:** `pt` (padrão), `en`

---

## Decisões

| Questão | Decisão |
|---|---|
| URL structure | Subpath routing: `/pt`, `/en` |
| Conteúdo traduzido | Tudo — UI labels + dados de projetos e timeline |
| URL raiz `/` | Redirect automático pelo `Accept-Language` do browser |
| Biblioteca | `next-intl` |

---

## Arquitetura

### Estrutura de rotas

```
app/
  layout.tsx                        ← só <html> e <body>, sem locale
  [locale]/
    layout.tsx                      ← NextIntlClientProvider + locale no <html lang>
    page.tsx                        ← homepage
    projects/
      [projectId]/
        page.tsx
  globals.css
  favicon.ico
```

### Middleware

`middleware.ts` na raiz, usando `createNavigation` do `next-intl`:

- Locales suportados: `["pt", "en"]`
- Locale padrão: `"pt"`
- `/` → detecta `Accept-Language` → redireciona para `/pt` ou `/en`
- Locale inválido (ex: `/fr`) → redirect para `/pt`

### Configuração next-intl

`i18n/request.ts` — lê o locale do request e carrega o arquivo de mensagens correspondente.

## Estratégia de tradução

### Tipo 1 — UI strings: `messages/`

Arquivos JSON com chaves de tradução para textos curtos de componentes:

```
messages/
  pt.json
  en.json
```

Namespaces:

```json
{
  "navbar": { "about": "...", "projects": "...", "services": "..." },
  "hero": { "greeting": "...", "role": "..." },
  "about": { "title": "...", "summary": "..." },
  "services": {
    "title": "...",
    "spa": { "title": "...", "description": "..." },
    "api": { "title": "...", "description": "..." },
    "database": { "title": "...", "description": "..." }
  },
  "footer": { "contact": "..." },
  "projects": { "title": "..." }
}
```

Componentes Server usam `getTranslations(namespace)`. Componentes Client (`Navbar`) usam `useTranslations(namespace)`.

### Tipo 2 — Dados estruturados: `constants/data/`

`projectData` e `timelineData` são arrays de objetos com campos aninhados — inadequados para JSON plano. Ficam como TypeScript tipado:

```
constants/
  types.ts          ← tipos ProjectData e TimelineData (extraídos do constant.tsx atual)
  data/
    pt.tsx          ← dados em PT (conteúdo atual de constant.tsx)
    en.tsx          ← dados em EN (versão traduzida)
  index.ts          ← getProjectData(locale), getTimelineData(locale)
```

```ts
// constants/index.ts
export function getProjectData(locale: string) {
  return locale === 'en' ? projectDataEn : projectDataPt
}
export function getTimelineData(locale: string) {
  return locale === 'en' ? timelineDataEn : timelineDataPt
}
```

As páginas (`app/[locale]/page.tsx`) leem o locale do param, chamam essas funções e passam os dados como props para `Timeline` e `Projects`.

## Mudanças nos componentes

| Componente | Tipo | Mudança |
|---|---|---|
| `Hero.tsx` | Server | `getTranslations('hero')` |
| `Summary.tsx` | Server | `getTranslations('about')` |
| `Services.tsx` | Server | `getTranslations('services')` |
| `Footer.tsx` | Server | `getTranslations('footer')` |
| `Navbar.tsx` | Client | `useTranslations('navbar')` + `LocaleSwitcher` |
| `Timeline.tsx` | Server | Recebe `data` como prop (em vez de importar constants) |
| `Projects.tsx` | Server | Recebe `data` como prop |
| `app/[locale]/page.tsx` | Server | Chama `getProjectData` e `getTimelineData` e passa como props |

### Correção de inconsistência existente

`Navbar.tsx` atualmente usa PT no desktop ("Sobre mim") e EN no mobile ("About"). Unificado com as chaves de tradução.

## Language Switcher

Componente `LocaleSwitcher` adicionado ao `Navbar.tsx`:

- Usa `usePathname` do `next-intl` para obter o path atual
- Gera link para o mesmo path com o locale alternado
  - Ex: `/pt/projects/fsw-foods` → link "EN" aponta para `/en/projects/fsw-foods`
- Visual: **PT | EN** — ativo em `text-blue-500 font-bold`, inativo em `text-slate-400`
- Sem dropdown, sem bandeiras — consistente com o estilo minimalista
- Posição: canto direito da navbar desktop; abaixo dos links no mobile Sheet
